Rules learned so far
- No process may load torch together with xgboost or lightgbm: both combinations crash (P0.2). Each model family runs in its own process; ensembles combine saved predictions.
- Do not start a task that builds on unreviewed results, even as a draft whose execution waits for approval (P1.4, F4). Generic code may be written ahead only if it encodes no unapproved result.
- Never edit code that a running job imports or will launch (P1.4 deviation above); write new work in new files. Run records hash code when the run ends, so an edit during a run corrupts provenance even when the executed code was unchanged.
- Thread limits: HistGradientBoosting has no thread parameter and uses every core unless limited. Runners limit all OpenMP and BLAS pools with threadpoolctl after importing the family's libraries (a limit reaches only libraries already loaded). numpy's BLAS here is Apple Accelerate, which threadpoolctl cannot limit. kNN tie-breaking among equidistant neighbours depends on the OpenMP thread count (P1.2).
- The holdout is sealed: no model or score uses its labels until the final audit. make_split.py used all labels for stratification when it built the split; until P1.3, common.development() parsed every label and then dropped the holdout rows (no computation used them; the P1.2 out-of-fold arrays hold development rows only); from P1.3 it never parses a holdout label. Earlier all-row runs saw the holdout, so it is a prospective holdout after preliminary exploration.
