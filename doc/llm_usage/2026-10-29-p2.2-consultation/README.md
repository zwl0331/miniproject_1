Roles: Claude Code (Claude Opus 5.5) is the author of P2.2. Codex advised and is not its reviewer; the formal review is a fresh Codex session. Consultation advice is input, not approval. Claude drafted code in a scratch worktree outside the project while round K ran, so Codex's design was independent of it.

Claude's positions against round K: both proposed two review checkpoints in one record, a fixed reference H (the LightGBM anchor), compact contribution records instead of blend banks, synchronized waves so that execution order cannot change allocation, serial execution, an audit separate from refitting, the banks committed to git, and Optuna kept out. Round K differed, and was adopted, on: P2.3's searches waiting for P2.2's completion rather than its first checkpoint; an initialization wave fitting the anchors after the initial lists are saved; the refinement families chosen right after the initial wave (two by standalone score, up to two by contribution) and the 3 broad plus 9 local split, 5/4 then 4/5, with the tree-count variants inside the local slots; the Manhattan normalization (1/10 and beta/6); parameter-domain validation; score-free timing that never calls the scoring engine; a full refit of every P2.2 run before the completion review; Findings 011 and 012; the predeclared rule for the optional submission; the hard bounds for range extension.

Changed from round K, with reasons: the execution protocol is section 15 of the phase 2 plan, not a separate file, because `doc/project_plan.md` gives each phase one plan file; `knn_blocks` stays in `models.py` beside the other preprocessing constructors, without an `audio_scaler` field, since only standard scaling is built; `subsample_freq` is absent rather than 0 when `subsample` is 1; log shards are not built because execution is serial; the wave 1 manifests name the runs that supply their state, resolved when the batch is judged, instead of a separate sealing step; the cutoff is Friday 05:00 PDT rather than 03:00.

Adopted from round L (17 items): (1) the canonical recipe hash attached to each run record from its manifest recipe, the run's recipe id checked; (2) a preflight of the whole wave before any fit (file, id, schema, protocol hash, sources, task, official split seeds, recomputed run ids, re-planning); (3) completion auditing that refuses missing runs, partial batches, stray task runs and an empty refit; (4) resumable planning, failure records, recovery of a finalized bank whose log record was lost, and a logged run reused only after its bank hash is checked; (5) the anchors-only initialization limited to wave 1 and covered by the cutoff, a required initialization before the search fits, and `batch_start` records governing the cutoff; (6) the H check against the P2.1 anchor bank, logged with both hashes; (7) duplicate records refused, exactly one contribution per declared weight bound to both bank hashes and the official seeds, complete runs checked by seeds and rows, incomplete batch members refused; (8) bootstraps of the decision-driving comparisons by a declared witness rule, recomputed by the audit; (9) the self-checks repaired and extended (kNN, an in-memory verification fixture under the current sources, orchestration, preflight, resume, cutoff, tampering, duplicates, H check, timing with every scorer disabled); (10) a comparison key that treats equivalent numbers and omitted factory defaults as one configuration; (11) the contribution parent restricted to qualifying configurations, and G fixed to H in wave 1 and to closed waves later; (12) fractions required to be floats, XGBoost depth an integer, protocol-level validation, admissibility of explicit and grid members; (13) exhaustion proven by enumeration, an attempt limit never mistaken for it, and `verify_searches` checking the recipe hashes and rejection counts; (14) timing provenance and a reservation record; (15) the kNN tie wording and its synthetic cases, the F1 exact-match limitation documented; (16) a blend audited against its declared weighted parents; (17) the readiness documents, commands and refinement table.

Not adopted from round L: in item 12, the Extra Trees fallback default for `max_features` stays "sqrt", because scikit-learn 1.9.1's `ExtraTreesClassifier().max_features` is "sqrt" (1.0 is the regressor's default), checked in the project environment.
