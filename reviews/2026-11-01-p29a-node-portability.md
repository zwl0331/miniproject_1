Findings:
  F1 [blocking] doc/plans/phase2-p29-other-methods.md lines 34, 60, 121, 188, 206. The amendment rewrote sections 2, 6.1 and 10 but left dependent requirements that still demand historical reproduction: section 3 defines P2.9b's complete result as "historical baseline reproduction"; section 5 requires arm B to "replay original TabM recipe"; section 7 lets "historical exact scientific controls count once toward distinct coverage" if recipe/source compatibility is verified, which contradicts 6.1's "such historical runs cannot count as P2.9 scientific controls"; section 11 lists "historical replay" among the items presented to Sam; section 12's execution completion requires "old deployment atoms reproduced". With measured Mac differences of 0.16, 0.096, 0.033 and 0.011 for XGBoost, CatBoost, Extra Trees and TabM, these criteria are either unmeetable or silently reinterpreted, the exact outcome the amendment exists to prevent. Correction: amend each to the same-route wording (fresh-process node reproduction of final-source atoms at 1e-12, bitwise expected; cross-platform differences reported and never called reproduction; historical Mac runs excluded as scientific controls; the launch-proposal item renamed "portability measurement"), then recheck.
  F2 [non-blocking] doc/plans/phase2-p29-other-methods.md line 27; doc/plans/phase2-p29-node-contracts.md line 13; songpop/phase2/runs.py:82-96. The amendment requires the fresh node E bank to have "a new run identity including the platform/runtime route", and the contracts put the route identity in "P2.9 recipes". E's atoms are recipe_v1 and must stay exactly E's procedure, so the route cannot enter their recipe hash; `fitted_config` has no route field and `packages_for` records 2.14.1, not 2.14.1+cu130. As specified, the node atoms' run ids would differ from the historical ones only incidentally through the source manifest. Correction: specify the route identity (policy id, lock hash, runtime build strings) as a field of the run config and of nested cache keys, independent of recipe schema; state that the array comparison with historical E is arrays-only, since `compare_v2` will also report STABLE metadata differences.
  F3 [non-blocking] doc/plans/phase2-p29-other-methods.md lines 156-160, 178.
