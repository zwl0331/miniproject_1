- Ran in-memory corruption probes against bank and CV validation, including a mocked bank save. No project file was modified.

Findings:

- F1 [blocking] `songpop/evaluate.py:84–94`. Bank validation accepts a NaN stored fold AUC. The finiteness check excludes `fold_auc`, and `abs(recomputed_auc - NaN) > tol` evaluates false. Setting the LightGBM F2 bank’s `fold_auc[0,0]` to NaN passed `validate_bank`, mocked `save_bank`, and `load_bank`; `summarize` then returned a NaN selection metric. Require finite fold AUCs in [0, 1] before checking their agreement with recomputed values. Add regression checks for NaN and infinity through validation and loading.

- F2 [blocking] `songpop/evaluate.py:33–46`. Missing group IDs bypass the group-separation guard because pandas `groupby` drops missing keys. Replacing every group ID with NaN passed both `validate_cv_inputs` and bank validation despite those entries spanning every fold. This allows an invalid grouping to reach fitting without the promised leakage check. Reject missing group IDs before grouping, require a one-dimensional group vector, and test rejection before the estimator factory is called.

- F3 [blocking] `songpop/artifacts.py:131–189`; `doc/plans/phase1-data-baseline.md`, section 4.8. The specified submission file writer and read-back verification are absent. `submission_bytes` serializes in memory, and `validate_submission` checks supplied bytes. No function writes a submission, rereads its persisted bytes, and validates and hashes those bytes. The submission self-check also exercises only memory serialization. Implement the specified writer, returning validation of the bytes read from its destination, and test the read-back path with mocked I/O. Producing the actual first submission remains P1.3 work.

- F4 [non-blocking] `doc/findings.md:248`. “At most 0.0021” is not a valid upper bound. The independently recomputed maximum is 0.002122038557714645 for logistic F1. Use “about 0.0021” or an upper bound rounded upward, such as 0.0022.

Notes: The saved baseline results and comparison tables reproduced. F1 and F2 concern demonstrated validation failures on malformed inputs, not corruption found in the supplied banks. Sandbox-related temporary-file and CPU-detection warnings occurred, but all three verification commands completed successfully. No findings are deferred or contested.
